# Workflow：任務收尾，記下已經想過的事

**每個任務結束前都要做。** 目的：這次推理、搜尋、試錯得到的結論，下次直接拿來用，不必再花 token 重新推一次。

card.md 的「收尾」段落是本文件的濃縮版，日常照 card 做即可；不確定該記什麼時才讀本文件。

---

## 收尾檢查（依序問自己）

| # | 這次任務中…… | 記到 | 格式 |
|---|---|---|---|
| 1 | 新增或修改了 entity、port 方法、use case、adapter、路由？ | `map.md` 對應模組 | 每項一行：名稱（位置）— 要點 |
| 2 | 做了需要推理的判斷？（放哪一層、怎麼切模組、選 A 不選 B） | `decisions.md` | `## DEC-N [模組][主題] 結論` + 理由 / 否決 |
| 3 | 花力氣調查才搞懂某件事？（某段舊程式的行為、某個框架限制） | `decisions.md`，標 `[調查]` | 只寫結論與相關檔案 |
| 4 | 找到或試出可用的指令？（測試、啟動、lint、migration） | `card.md`「常用指令」 | 一行一個指令 |
| 5 | 發現專案慣例與 skill 預設不同、或被使用者糾正？ | `conventions.md` | 見 [record-convention.md](record-convention.md) |
| 6 | 發現違反硬規則的既有程式碼？ | `debt.md` | 同上 |
| 7 | 試了某個做法失敗？（例如某套件在此專案無法使用） | `decisions.md`，標 `[否決]` | 寫失敗原因，避免下次再試 |

全部都「沒有」→ 不寫任何東西，這是正常的。

## 記什麼 / 不記什麼

| ✅ 記 | ❌ 不記 |
|---|---|
| **結論**（一句話） | 推理過程、思考草稿 |
| 下次會再遇到的問題 | 只跟這次任務有關的臨時決定 |
| 要花 ≥ 2 次搜尋或讀 ≥ 2 個檔案才得到的資訊 | 一次搜尋就找得到的事 |
| 使用者明確確認過的取捨 | 尚未確認的猜測（要記就標「未確認」） |
| 業務規則的**編號與位置**（map.md） | 業務規則的完整內容（程式碼與測試才是依據） |
| — | 密碼、token、連線字串、個人資料 |

## 下次怎麼用（讀取規則）

| 時機 | 讀什麼 | 怎麼讀 |
|---|---|---|
| 每個任務開始 | card.md + conventions.md | 全讀 |
| 要修改或新增程式碼 | map.md | 全讀（大型專案只讀相關模組的 `map/<module>.md`） |
| 要做設計判斷之前 | decisions.md | **只搜尋標題**：`^## DEC-.*\[<模組或 entity>\]`，命中才讀該條 |
| 審查 / 重構 | debt.md | 全讀 |

命中 decisions 條目時：**直接採用結論**，並在回覆中提一句「依 DEC-003」。不要重新推理。

## 過時處理

- 記錄與程式碼不符 → **以程式碼為準**，修正記錄，告知使用者一行
- 使用者推翻某個結論 → 修改原條目（更新日期與理由），不新增矛盾條目
- 檔案超過上限（map 150 行、decisions 200 行、conventions 80 行）→ 合併、刪除過時條目，或依模組拆檔

## 告知使用者

收尾時用**一行**列出這次記了什麼，例如：

```
已更新記憶：map（RenewLoan、LoanRepository.findById）、DEC-004（續借規則放 Loan）、常用指令（npm test）。
```

沒有記任何東西就不用提。
